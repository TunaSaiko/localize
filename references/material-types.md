## 1. 类型表与风险重心

同一套方法，不同材料的风险重心不同。判断在哪一栏，然后把默认优先级按这一栏重排。

| 材料类型 | 风险重心 | 特别注意 |
|---|---|---|
| **投资/商务提案** | 数字、事实、功能性文本 | 受众会验证每个数字并追问出处；免责条款必须保持法律功能；确定性不能上调 |
| **合同/条款类** | 功能性文本、定义一致性 | 术语必须机械一致（不适用"概念映射微调"规则）；歧义比生硬更危险；通常需要法务复核 |
| **社群/活动公告** | 语体、字符级错误、时效信息 | 母语者对错字的容忍度远低于对生硬的容忍度；日期时间地点报名方式逐一核对 |
| **产品 UI / 应用内文案** | 长度、术语一致性、动态拼接 | 见 §3 |
| **技术文档** | 术语准确性、可操作性 | 行话用目标市场开发者实际在用的词；代码/命令/参数名不翻译；步骤顺序不能因语序调整而错乱 |
| **市场/品牌文案** | 语感、文化适配 | 唯一"可以大幅偏离源文"的类型；直译几乎必然失败；口号往往需要重写而非翻译；触发 §4 |
| **官网/落地页** | 混合（信息+说服+SEO） | 分区处理；SEO 关键词不能直译，用目标市场实际搜索词（WebSearch 验证） |

## 2. 每类的具体调整

**投资/商务提案**
- 优先级：G1 事实 > 功能性文本 > 确定性 > 其余。
- "确定性被上调"在这里默认 critical（会变成可追问的承诺）。
- 每个数字要能回答"出处是什么"；换算（币种、单位）要标明换算日或口径。
- 日本受众：大数单位用 億/兆 比 B/T 认知快一个数量级。

**合同/条款类**
- 术语开关设为"机械一致"：同一概念全篇同一字符串，包括名词组合内部。
- 定义条款里定义过的词，全篇必须原样使用。
- 否定、例外、期限、责任主体逐句单独过。
- 报告末尾必须写"需法务复核"。

**社群/活动公告**
- 快速档即可：脚本 + 单语遍 + G1/G5/G6。
- 日期、时间（含时区）、地点、报名方式、截止、费用逐项对照。
- 语体按平台惯例（日本开发者社群常用です・ます体，口语化但不失礼）。

**技术文档**
- 代码块、命令、参数名、错误信息原文、文件路径一律不翻译；UI 元素名用产品实际的目标语 UI 文案。
- 步骤编号与源文一一对应。

**市场/品牌文案**
- 允许重写。审校时不按"信息颗粒"计数，按"意图是否等价"判断。
- 口号、标题：给三个方向的重写而不是三个措辞。
- 触发 §4 法规检查。

**官网/落地页**
- 分区：导航/按钮按 UI 规则；产品描述按技术文档；宣传语按品牌文案；页脚/法务按合同。
- SEO：关键词用 WebSearch 查目标市场的实际搜索词，不直译。

## 3. UI / 软件字符串的 i18n 层

中↔日单语对时感觉不到，一做 UI 或多语并行就会出问题。材料类型 = UI 时启用：

| 项 | 规则 |
|---|---|
| **长度** | 字符串有硬约束宽度。短串膨胀率最高（≤10 字符的英文源串译成欧洲语言可达 200%–300%）。中日英之间：字符数常收缩，显示宽度和行高膨胀。跑 `length_estimate.py --max-em` |
| **复数** | CLDR 复数类别：日语、中文只有 `other`；英语 one/other；俄语/波兰语 4 类；阿拉伯语 6 类。目标语复数类别比源语多时，一条源串要拆成多条 |
| **拼接** | `"Page %d of %d"` 这类拼接在部分语言不可译（语序不同）。发现变量拼接就报 major 并建议改为整句占位（ICU MessageFormat） |
| **占位符** | `{name}` `%s` `%1$d` 数量与顺序必须与源串一致（`fact_check.py` 会列出） |
| **术语** | 同一功能在不同界面必须同名（机械一致开关打开） |
| **全角波线** | 软件字符串禁用「〜」（U+301C），会导致构建错误；改「から」或半角连字符 |
| **伪本地化** | 上游可用 +40% 长度的伪本地化提前暴露截断与拼接（Microsoft 经验值） |

## 4. 法规敏感表述触发

以下表述出现时，在报告里单列"法规触发"并建议法务/合规复核。本 skill 不做法律判断，只做触发提醒。具体条目在各 locale 包的"法规敏感"节。

**降级表述强度时，先读 `diagnostics.md` §10**：功能描述照常肯定，只有效果承诺才留余地，免责另起一句。把功能描述也软化是常见的做过头。

| 触发 | 典型 |
|---|---|
| 最高级/唯一性断言 | No.1、最安、業界初、世界初、唯一、最大、最高 |
| 健康/医疗功效 | 治す、効く、改善、予防（日本受薬機法约束） |
| 金融/投资劝诱 | 保証、確実、元本、必ず（日本受金融商品取引法约束） |
| 绝对化用语（中国大陆） | 国家级、最高级、最佳、第一（广告法第九条） |
| 比较广告 | 与竞品直接对比 |
| 加戏产生的断言 | 源文没有、译文多出来的宣传性表述，同时是 major/critical 发现 |
| **用户评价/证言的署名与国籍** | 见下方专条 |

**用户评价（体験談・口コミ・testimonial）单列一条，因为它的错法不像别的。**

评价正文可以译，**署名不可以本地化**。把 `Mike R.` 改成「田中太郎」不是翻译，是伪造证言。

法条对应要分清（本 skill 只做触发提醒，不做法律判断）：
- **自家落地页上编造署名 → 景品表示法第 5 条 1 号 優良誤認**。这是主要风险。
- ステマ規制（令和 5 年内閣府告示第 19 号，2023-10-01 施行，景表法 5 条 3 号）管的是**"看不出这是广告"**，
  典型是找网红/测评者发帖不标注 PR。自家官网的评价区显然是自家表示，通常不落在这一条。
  **别把两条混着用**——写报告时指错法条会让业务侧误判整改方向。
- 中国大陆：广告法第二十八条（虚假广告）。

正确的做法只有两种，都要业务侧拍板：署名保持原样并说明是海外用户的评价；或者整块不上线，
等目标市场的真实评价。**"译得更像本地人写的"在这里是反效果**：正文越自然、署名越突兀，
读者越容易判断成编造。

检测上有个便宜的信号：**评价区的署名栏在 `deliverable_check.py` 里会被报"文字体系不符 + 源文残留"。**
别急着当误报放行，先确认它是不是这一条。

## adapt 操作型材料：增加任务测试

帮助文档、教程、安装指南、UI 文案等不仅要测自然度，还要让目标用户按成稿执行预登记任务。记录菜单、按钮、命令、文件格式、条件、顺序和下一步是否可执行；失败分为语言不清、源文缺陷、产品/界面变化。adapt 版关键任务成功率不得低于 translate 版，更自然但更难操作即失败。模板见 `templates/task-test.md`。

## 外币金额：面向读者做判断的材料，必须给目标市场货币的换算

**适用**：投资提案、面向消费者的价格页、报价单——凡是读者要**据此做判断**的材料。

**实测（某商业提案，外币计价 → ja）**：流程决定「不换算日元、不标汇率」，理由是数值不许改 + 汇率需基准日且会过期。
对照的人工完成品**做了换算**（26 处 + 汇率注记）。**三位日本母语者全部指出不换算是问题**：
外币金额没有量感；日元在前、原币在后才能一眼看出大小；
「頭の中で都度計算しなければならず、**大きなストレス（読むのをやめる原因）**」。

**教训**：「汇率会过期」是**维护成本**，「读者算不过来就不读了」是**读者成本**。
**读者要在几十分钟内做去留判断时，读者成本压倒维护成本。**
汇率过期用**基准日注记**解决（`1元＝○○円、20XX年X月X日レート`），**不能用"不换算"解决**。

**顺序也有讲究**：目标市场货币在前、原币种括号在后（如 `約2.1億円（1,000万元）`，数字为示意），
不是反过来——读者第一眼要看到自己有感觉的那个数。
