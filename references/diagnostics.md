## 1. 三步法与判定测试

```
源文
  ↓ ① 意图抽出   这句到底想说什么？（脱离字面）
真正的意思
  ↓ ② 场景重建   目标语的人在这个场景会怎么写？
目标语原生表达
  ↓ ③ 语感打磨   语体、长度、与全篇的一致性
成品
```

关键在第 ② 步。它不是"翻译"，是**用目标语重新写一遍**。判断标准不是"意思对不对"，而是"目标市场的人写这份材料，会不会写出这句话"。

**三秒判定测试**：我为什么选这个词？
- 理由是"源语也是这个形式" → 在翻译
- 理由是"这类材料就是这么写的" → 在本地化

## 2. "能看懂"为什么是陷阱

直译流程优化的目标是可理解性；本地化的目标是看起来像本地写的。两者在大部分句子上重合，分岔的地方恰好是母语者最敏感的：既有说法、搭配、褒贬、语体一致。结果是材料 90% 正确，整体却给人"这是译稿"的印象。在正式场合，"这是译稿"本身就是负面信号。

实证：译后编辑产物比人工翻译更简化、更规范化、源语干扰更强（Toral 2019, "Post-editese"）。"看起来对"的流程会把译稿味道放大。

## 3. 五类只有对照才能发现的错误：检测步骤

核心结论：只审译文存在结构性盲区。参考数据：某项目只看译文审出 129 条；对照源文后又发现 42 条，其中 4 条是实质性错误，这 4 条单看译文都是通顺的句子。

**检测顺序**：先只过标题和功能性文本（数量少、伤害大），再逐句过信息颗粒。

| 类别 | 症状 | 检测步骤 |
|---|---|---|
| **方向错误** | 收/付、给/取、上游/下游、买/卖反了 | 找出所有涉及利益流动、责任归属、因果的句子；逐句写出"谁→谁"，对照源文 |
| **关键限定词漏译** | 合作→数据、纯软件→软件、已覆盖→覆盖、部分→全部 | 用 §8 信息颗粒计数法：源文 5 个信息点译文只有 4 个就停 |
| **确定性被上调** | 传闻→报道、可能→将会、预计→已经、约→（删） | 在源文里挑出所有表示不确定的词（传闻、据说、预计、约、可能、有望、初步、暂定、计划），逐个确认译文的确定性等级没有升高；也查反向（承诺被弱化） |
| **功能性文本失效** | 免责声明变流程说明；承诺变描述；否定丢失 | 找出所有"有法律或商业功能"的句子（免责、条款、保证、限定、否定），单独问：这句还在起原来的作用吗？ |
| **定位/框架偏移** | 标题语义变了，整节被重新定性 | 所有标题、章节名、图表标题单独过一遍，问：这个标题下的内容还是同一种性质吗？ |

## 4. 模型特有的四种失败

人很少犯、模型常犯，放在双语遍里作为独立检查项：

| 失败 | 检测 |
|---|---|
| **漏句** | 逐段数句子；源文 N 句译文 N-1 句即停。长文档尤其常见整段消失 |
| **加戏** | 译文里有源文没有的信息点（尤其是"業界No.1""世界初"这类，还会触发法规问题） |
| **过度润色改义** | "尝试了"变"成功了"，"部分"变"全面"。信息颗粒计数能抓一部分；另问：改得更漂亮的句子，语义等级有没有变 |
| **审校顺从** | 审校 subagent 倾向说"没问题"，尤其译文是模型自己刚生成的。对策：生成与审校分上下文；怀疑论者只负责挑刺不负责通过；报告必须显式写"发现数"和"未审查段落" |

## 5. 词汇风险四触发器 + 褒贬色彩（模型执行版）

固定词表只对特定语对有用；触发器是通用的，用它现场生成本项目的风险清单。**模型不能靠"我记得见过"，每一条都要有下面写明的验证动作。**

| 触发器 | 说明 | 模型的验证动作 |
|---|---|---|
| **T1 同形词** | 源语和目标语共享书写形式（汉字圈尤甚；拉丁语系 cognate 同理） | 默认是假朋友，直到验证为真。先查语对包；不在包里 → WebSearch 目标语真实用例（不是词典释义）；找不到 → 标「未验证」 |
| **T2 举不出出处** | 词看起来合法，但说不出在哪份目标语材料里见过 | 模型没有可靠的"我见过"记忆。用 WebSearch 找该词在目标语**同类材料**（同行业、同文体）里的真实用例；命中少或只在译文类页面出现 → 大概率是拼出来的，换一个能举出出处的词 |
| **T3 外来语/音译** | 片假名、音译、字母缩写 | 确认是目标市场**既有**说法而非"听起来合理"的造词。日语：参考国立国語研究所「外来語」言い換え提案的理解率分级，并考虑受众年龄层 |
| **T4 源语的行话** | 源文里是专业术语的词 | 目标语的对应行话往往是完全不同的词。搜目标市场同行业的原生材料，看他们叫什么 |

实证支撑：懂中文的日语学习者在汉日同形异义词上的表现显著差于完全不懂中文的英语母语者（加藤 2005）。母语知识在这里是负迁移，所以 T1 默认怀疑是对的。

**褒贬色彩**：同义不同色的词，是"看得懂但印象变差"，比看不懂更伤，因为它不会被察觉，只会累积。检测：把所有涉及**钱、地位、规模、合法性**的词单独挑出来，问"这个词在目标市场有没有负面联想"。例：転売（黄牛）、下流（阶层联想）、冗長（啰嗦）。

## 6. 符号与单位清单

问题本质：符号在不同 locale 有不同语义，但长得一样，所以翻译流程会跳过它们。**先跑 `scripts/fact_check.py`**，再逐项人工确认：

| 类别 | 陷阱 |
|---|---|
| 货币符号 | `¥` `$` `£` 在不同市场指向不同货币；`$` 至少十几种 |
| 小数与千分位 | `1,000` 在部分欧洲市场是 1.0 |
| 大数单位 | 万/億/兆 vs K/M/B/T，不只是换算，是认知速度差一个数量级 |
| 日期 | MM/DD vs DD/MM vs YYYY-MM-DD；年号 vs 公历 |
| 姓名顺序 | 姓前还是名前；是否并记罗马字/当地文字 |
| 地址、电话 | 顺序和格式完全不同 |
| 度量衡 | 公制/英制；纸张尺寸 |
| 法人后缀 | Inc. / GmbH / Pte. Ltd. / 株式会社 不能互换，通常保留原文 |
| URL | 译文有没有擅自加语言路径？该路径真实存在吗 |
| 联系方式优先级 | 有的市场邮件优先，有的即时通讯优先 |

**规律**：涉及符号和单位的地方必须回源文确认，不能从译文推断。参考案例：源文 `¥` 表示人民币，译文原样保留，目标语中 `¥` 专指日元。只看译文判断为 2 处局部矛盾；对照源文后是全篇 25 处系统性问题，所有价格被读成 1/20。**从译文推断会低估影响范围。**

## 7. 术语决策三关

1. **是不是既有词？——问的不是"日语里有没有"，是"给这类读者看的材料里有没有"。**

   ```
   ❌ 「<候选词> は日本語で使われているか」 → 某厂商の技術ブログで見つかる → 通过
   ✅ 「<候选词> は【<读者> 向けの<材料类型>】で使われているか」 → 見つからない → 不通过
   ```

   **同一个词、同一次检索，只因为加了"给谁看"这个限定，结论就反过来。**

   **实测四次同型失败，根因全是这一条**：出处分别是别家的产品页（→那是别家产品能做、材料中的产品做不到的事）、
   通用词典（→日语里只用于另一个领域）、无出处的自造刻度（→在目标读者的材料里是过大表示）、
   厂商的**技术**博客（→业务读者说这个词在他们的语境里几乎不用）。
   **出处找对了语言，找错了读者。**

   **动作**：检索时把 `00-brief.md` 的场景一句话拆成检索限定词
   （材料类型＋读者身份，例：`事業計画書` `IR資料` `ピッチデック` `投資家向け`），**和词一起搜**。

   **举不出出处就是拼的。而"限定读者后找不到用例"本身是有效结论**——
   比"泛泛搜到了"强得多。找不到就标「未验证」并进待确认清单，
   **不许因为"换个宽泛的搜法能搜到"就当通过。**
2. **会不会和文内已有的词撞车？** 目标语里合适的词可能已被另一个概念占用。查 `glossary.md` 的"已占用词"。
3. **放得进版式吗？** 选词时就预估长度，不要等排版才发现。

**补充规则**：同一概念在不同名词组合内部可以微调，这不算不统一。统一的是**概念到词的映射**，不是**字符串的机械一致**。例外：合同/条款类和 UI 字符串要求机械一致（见 `material-types.md`）。

## 8. 信息颗粒计数法

对每个源文句子列出信息点：主体、客体、动作、限定词（纯/仅/已/部分/全部）、数量、时间、情态（可能/将/已）、否定。数一数。再对译文数一遍。数目不等就停下来找。

例：
```
源：我们已为 3 家合作伙伴提供纯软件方案
颗粒：我们 / 已 / 3 家 / 合作伙伴 / 提供 / 纯软件 / 方案  = 7
译：3社にソフトウェアソリューションを提供しています
颗粒：3社 / ソフトウェア / ソリューション / 提供 / している = 5
缺：已（完成态被弱化为进行态）、合作伙伴（变成任意 3 家）、纯（限定词丢失）
```

## 9. Few-shot 例子集

给 subagent 的提示词里至少带每类一个。构造例：错误类型取自真实项目，句子为示意。

### 9.1 方向错误（critical）
```
源：平台向商户收取 3% 的服务费
译：プラットフォームは加盟店に 3% のサービス料を支払う
问题：收取→支払う，钱的流向反了
改：プラットフォームは加盟店から 3% のサービス料を徴収する
```

### 9.2 关键限定词漏译（major；在合同/投资材料 critical）
```
源：仅限企业客户使用
译：企業のお客様にご利用いただけます
问题：「仅限」丢失，限定变成描述
改：ご利用は法人のお客様に限ります
```

### 9.3 确定性被上调（major；投资材料 critical）
```
源：据传闻，该公司计划明年上市
译：同社は来年上場すると報じられている
问题：传闻→報道，且「计划」变「将」
改：同社が来年の上場を計画しているとの噂がある
```

### 9.4 功能性文本失效（critical）
```
源：过去业绩不代表未来表现
译：過去の実績は将来の成果を示しています
问题：否定丢失，免责声明变成了承诺
改：過去の実績は将来の成果を保証するものではありません
```

### 9.5 定位/框架偏移（critical）
```
源：（章节标题）风险提示
译：リスク管理
问题：整节从"提醒读者风险"变成"我们如何管理风险"，性质变了
改：リスクに関する注意事項
```

### 9.6 假朋友 / 同形词（major）
```
源：支持转售
译：転売に対応
问题：転売 在日语强负面（黄牛、倒卖）
改：再販に対応 ／ リセールに対応
```

### 9.7 生造词 / T2（major）
```
源：一套解决方案
译：一套のソリューション
问题：「一套」日语不存在
改：一体型のソリューション ／ ソリューションを一つにまとめて
```

### 9.8 褒贬色彩（minor；高曝光营销 major）
```
源：面向下游客户
译：下流の顧客向け
问题：下流 有阶层负面联想（供应链语境下"川下"才是行话）
改：エンドユーザー側の顧客向け ／ 川下の顧客向け（供应链语境）
```

### 9.9 符号（critical，系统性）
```
源：售价 ¥1,200（人民币）
译：価格 ¥1,200
问题：目标语中 ¥ 专指日元，读者按 1/20 理解；全篇每处价格都受影响
改：価格 1,200 元（約 xx 円）— 换算与否按场景定，但必须标明币种
```

### 9.10 字符规范（minor）
```
译：東京·大阪   →  東京・大阪   （U+00B7 → U+30FB）
译：10~20%      →  10〜20%      （ASCII ~ → U+301C；软件字符串则用「10から20%」或半角连字符）
译：約～100     →  約100         （日语「〜」不表示"大约"）
```

### 9.11 不该误杀（neutral，SNF＝should-not-flag，不该报的情形）
```
译：コンピュータ  → 内閣告示允许省略长音符；只判「全文统一」，不判错
译：中古車の転売  → 二手车行业语境下 転売 是中性行话，不改
译：3社に提供 vs 3 社に提供 → 空格策略是项目级开关（JTF 不加 / Microsoft 加），只报一致性
译：術語 A 在「Aシステム」和「A機能」里写法微调 → 概念映射一致即可，非合同不报
```

## 10. 表述强度的两分法（软化该落在哪里）

**问题**：受众市场对广告表述有约束时（几乎所有市场都有），译者会把断定改成留余地的说法。做过头，整篇文案会失去底气，而且合规上并没有多得到什么。

**判据（语言无关）**：先分清这一句说的是哪一种。

| 类型 | 说的是 | 可验证性 | 怎么写 |
|---|---|---|---|
| **功能描述** | 产品**做了什么动作** | 可验证——要么执行了要么没有 | **照常肯定** |
| **效果承诺** | 用户**会得到什么结果** | 不可保证——取决于输入条件 | **留余地** |
| **免责** | 结果因条件而异 | — | **另起一句**，不要塞进主张句里 |

三者的关系：

```
功能描述   音声を自動で文字起こしします。                  ← 肯定
效果承诺   議事録作成の手間を減らせます。                  ← 这里才留余地
免责       ※認識精度は録音環境により異なります。          ← 独立一句
```

**常见的做过头**：
- 把功能描述也软化（"自动生成字幕" → "字幕生成が期待できます"）。字幕确实在生成，这是事实不是承诺。
- 一段之内连用三次以上留余地的说法，读起来像还没做到。
- 用"以…为目标"来描述已经实现的功能，字面变成了尚未达成。

**检测**：把段落里所有句尾标出来，逐句问"这句说的是产品做什么，还是用户得到什么"。前者却用了留余地的句尾，就是做过头。**同一段内留余地的句尾超过两处**，回去重看是不是把功能也软化了。

**反向也要查**：效果承诺用了肯定句尾，是确定性被上调，属实质错误（见 §3）。

具体的法规依据放在各 locale 包（如 ja-JP §6、zh-CN §4），本节只定判据。

## 11. 改写的边界：措辞可改，所指不可改

**可以改**：句式、词、语序、信息编排、长度。品牌文案甚至可以整句重写（见 `material-types.md`）。

**不可以改**：源文指的那个东西。用途、对象、数量、主体、时间、方向。

**为什么单列一条**：译者发现源文的事实有问题时，最自然的反应是"顺手修正"。但这有三重代价：
1. 你在替作者做事实判断，而你手上的信息比作者少。
2. 改完通常会跟上下文的另一句矛盾——源文的其他地方还按原来的说法写着。
3. 作者永远不知道原文有这个问题，下一版还会重犯。

**正确做法**：措辞照译或按原意重写，把事实问题记进待确认清单，写清楚"源文说 X，但与同页的 Y 矛盾／与外部事实不符"，交作者裁决。

**判定测试**：改完之后，源文里被指的那个东西还是同一个吗？
- 换了个说法指同一个东西 → 改写，允许
- 指向了另一个东西 → 越界，退回并记待确认

**例**（示意，改编自真实项目）：源文说某档套餐适合"大型活动"。译者判断该档的人数上限撑不起大型活动，把用途换成了"中型研讨会"。结果：所指变了，而且跟前一句"中型研讨会选低一档"直接矛盾。正确做法是照译，并记一条待确认问作者这个用途是否有实际案例。

### 10b. 留余地要挑语域——降低确定性 ≠ 降低正式度

同一个"不确定"，可以用**低语域**的词，也可以用**高语域**的词，**认识论强度完全一样**：

| 语域 | 日语例 | 读起来像 |
|---|---|---|
| 低 | 噂 / らしい / かもしれない / と言われている | 八卦、道听途说 |
| **高** | **推計 / 想定 / 見込み / 一部報道による / 試算** | 专业、审慎 |

**投资、法务、医疗这类材料一律走高语域侧。**

实测（商业提案）：为防确定性上调，把源文的「传闻作价 X 亿美元」（金额已替换）译成 `評価額X億米ドル超との噂`——
**hedge 是对的，语域错了**。三位母语者：「**との噂**」はかなり口語的／**情報の確度を疑わせるため避けるべき**。
对照组（人工译者）用 `観測`，同样被批「サイエンスを連想させ不自然」——**两版都栽在语域上，没人栽在 hedge 本身**。
母语者给的正解：`（一部報道による）推計評価額` / `想定評価額`。

**判据**：写完 hedge 之后问一句——**"这个词如果出现在对方的律师函/尽调报告里，违和吗？"**
违和就是语域掉了，换高语域的同义 hedge，**不要因此把 hedge 去掉**。
