## 1. 严重度判定细则

四级：**critical / major / minor / neutral**。一条 critical 即"不通过"。

| 情形 | 默认级别 | 升级条件 |
|---|---|---|
| 货币、数量级、日期、单位错 | critical | — |
| 方向错误（利益流动、责任归属） | critical | — |
| 功能性文本失效（免责、保证、否定） | critical | — |
| 标题/章节定位偏移 | critical | — |
| 关键限定词漏译 | major | 合同/投资材料且改变义务或范围 → critical |
| 确定性被上调/下调 | major | 投资材料且变成可被追问的承诺 → critical |
| 漏句 | major | 漏的是功能性句子 → critical |
| 加戏 | major | 加的是宣传性断言（No.1、世界初）→ critical（法规） |
| 假朋友、生造词 | major | 是全篇核心术语 → critical |
| 术语撞车 | major | — |
| 过度润色改义 | major | — |
| 术语不统一 | minor | 合同/UI 字符串 → major |
| 褒贬色彩 | minor | 高曝光营销材料 → major |
| 字符规范、标点、空格 | minor | — |
| 语体断裂 | minor | 全篇正式度与场景不符 → major |
| 语感、更地道的说法 | neutral | 导致误读 → minor 以上 |

## 2. 错误 vs 偏好

每条发现先过这个测试：**一个拿着同一份场景定义的合格审校者，会不会拒绝现在的写法？**
- 会 → 是错误，按上表定级
- 不会，只是"我会写得不一样" → neutral，给出可选改法但不计入错误数

三选项格式里，neutral 条目只给"推荐"一个选项，不给保守/替代。

## 2b. 严重度的经验校准（来自一次带答案的真实回归：15 页商业提案）

一次 15 页商业提案的实测：合并出 122 条发现，其中 critical 4 / major 45；独立怀疑论者复核后 **维持 20、降级 28、驳回 1**（57% 的 critical/major 被降级）。教训写在这里，定级时先过一遍：

**A. 容易判过重的五种情形**（默认先按低一级起判，有下列加重理由才升）：
1. **单个修饰词脱落，但同页/同栏另有线索可还原** → minor。例：里程碑漏了一个修饰词，而同一里程碑在另一页写全了。
2. **术语不一致但两处语境相隔远、误读风险低** → minor（术语不一致本来就默认 minor，只有合同/UI 才升）。
3. **确定性朝"更保守"方向偏移**（承诺被弱化、加了可能形）→ 通常 minor；只有"确定性被上调"才按投资材料升 critical。
4. **源文自身就松散/自造/请求形，译文忠实对应** → 记 open question 或 neutral，不算译文错误。例：源文自造的 KPI 名称，译文直译；源文保密句本身就是请求形。
5. **标题被削短但仍准确指向该页主题** → 版式/一致性 minor；只有语义变了（性质被重新定性）才 critical。

**B. 升级的硬条件**（满足才给 major 以上）：
- 该词是全篇核心术语且出现在主标题上；
- 丢失的是限定词/否定/方向，且无处可还原；
- 日语里该搭配根本不成立（如「冗長」不能单用作名词、「〜とのデータ」缺中心词）；
- 语对包表 A 直接命中且领域标注吻合。

**C. 一条流程结论**：怀疑论者要求"实测再判"。上述复核里有 2 条发现的**论据本身被 grep 推翻**（以为"同一概念两词并存"，实测源文自己就区分两个概念、译文一一对应）。所以复核 subagent 必须能跑 grep/Read，不能只凭清单裁定。

## 3. 系统性错误的计数

同一错误重复出现（如 `¥` 25 处、某术语全篇错），**合并为一条**，标「系统性」，写出现次数和全部位置。严重度按总影响定，不按单处定。报告头部的发现数按条数计，另注"其中系统性 N 条，涉及 M 处"。

## 4. 长文档的抽样

完整档必须全文。其他档位按下列优先子集抽样（按曝光和风险分层）：
1. 所有标题、章节名、图表标题、图注
2. 首段与末段、封面、联系方式页
3. 所有功能性文本（免责、条款、保证、价格、日期）
4. 数字密集段
5. 脚本标出差异的段
6. 上一版审校标记过疑问的段

抽样了就在报告头部写"抽样：N/M 段"，不写"全文"。

## 5. 怀疑论者规则

独立 subagent，只看合并后的清单里的 critical 和 major：
- 对每条问：源文真的是这个意思吗？译文真的没表达出来吗？有没有语对包/locale 包/场景能解释现有写法？
- **默认不确定即降一级**；明显误判即驳回并写理由。
- **改写测试**：按"推荐"选项把那一句改一遍，改后如果没有明显更好，降为 neutral。
- 不负责"通过"整份材料，只负责挑刺和降级。输出：维持 / 降级为 X / 驳回，各附一句理由。

## 6. findings.md 模板

```markdown
# 审校发现清单：<材料名>

## 头部
- 场景：<一句话>（已确认 / 未确认，按材料类型默认）
- 材料类型：<>
- 语对：<src> → <tgt>；目标 locale：<>
- 本次捷径：<>
- 档位：<完整 / 快速 / 事实 / 可读>
- 加载的包：pairs/<> ／ locales/<>（或"无包，降级运行"）
- 译文来源：<人译 / 机译 / AI / 上一版 / 未知>
- 抽样：全文 / N/M 段
- 发现数：N（critical a / major b / minor c / neutral d；其中系统性 s 条，涉及 m 处）
- 未审查段落：<segment 号列表，或"无">
- 脚本摘要：fact_check 候选差异 x 项；char_lint y 项；length 超限 z 行

## 一、全篇统一事项（先定这些）
1. 术语：<概念> 建议 <词>，否决 <词>（理由）
2. 符号与货币：<>
3. 语体：<>
4. 空格/长音等策略：<>

## 二、逐条发现（按严重度排，同级按位置排）
F-001 【位置】 类别 / 严重度 / 来源（单语遍 / 双语遍 / 脚本）
- 源文：
- 译文：
- 问题：
- 修改：1.（推荐） 2. 保守案 3. 替代案
- 理由：
- 怀疑论者：

## 三、待确认（读不出原意，等用户）
见 open-questions.md，此处列编号与一句话。

## 四、未做的事
- 本报告未经母语者复核。建议把"场景"和这个问题一起交给母语者：**这像不像本地写的？**（不要问"有没有错"）
- 版式：<未渲染 / 已估算，见 scripts-report.md>
```

## 7. 分层确认

1. **先定全篇统一事项**（术语、符号规范、语体、关键取舍）。
2. **再走逐条清单**。

反过来做一定返工，因为逐条的具体写法取决于第 1 层的决定。给用户看的时候也按这个顺序：先请用户定第一层，再给第二层勾选。**勾选前不改任何文件。**

## 8. 与 MQM 的对应（可选标签）

用户要对接行业工具时，可给每条加 MQM 标签：

| 本 skill 类别 | MQM 2.0 |
|---|---|
| 方向错误、限定词漏译、确定性上调、漏句、加戏 | Accuracy（mistranslation / omission / addition / overtranslation / undertranslation） |
| 假朋友 | Accuracy / Mistranslation / **False friend** |
| 逐句直译腔 | Accuracy / Mistranslation / **Overly literal** |
| 生造词、术语撞车 | Terminology / Wrong term |
| 术语不统一 | Terminology / Inconsistent use of terminology |
| 字符、标点、空格 | Linguistic conventions |
| 货币、数字、日期、姓名格式 | Locale conventions |
| 语体、褒贬 | Style / Language register；Audience appropriateness |
| 溢出、截断 | Design and markup / Truncation-text expansion |

注意：MQM 是错误分类学，不是工作法；三步法、两遍分开、五类对照错误是本 skill 的流程层，MQM 里没有。
