# 反馈包（可选，帮 localize 变好）

> 由 localize 在交付后生成。**提交前请你通读一遍**：确认里面没有客户名、产品名、人名、具体数字、网址、原文整句。
> 提交入口：https://github.com/TunaSaiko/localize/issues/new/choose （选「反馈包」模板，整段粘贴）。不提交也完全没关系。

- 语对：<src → tgt>　材料类型：<七类之一>　入口：<review / translate / adapt>　档位：<>
- skill 版本：<插件版本号或 git 提交号；不知道写「未知」>
- 脱敏检查：`feedback_check.py` 退出码 <0>（已对照源文、译文）

## 条目

| # | 类型 | 现象（最小片段，已脱敏） | 应该怎样 | 依据与强度 | 建议改哪里 |
|---|---|---|---|---|---|
| F1 | 母语者纠正 / 误报 / 漏报 / 新假朋友 / 规则不清 / 脚本问题 | | | 母语者 N 人一致 / 出处链接 / 脚本可复现 / 个人判断 | `references/pairs/…` 等，不确定就留空 |

**类型说明**
- **母语者纠正**：母语者指出、而 skill 没报过的问题（§9.1 的第二堆）
- **误报**：skill 报了、但其实没错的（写清楚为什么没错）
- **漏报**：skill 没报、后来发现是错的
- **新假朋友**：语对包里没有、但这次踩到的同形异义词或"字面对但不是业界说法"
- **规则不清**：skill 的说明自相矛盾、没覆盖到、或让你不知道该怎么做的地方
- **脚本问题**：脚本报错、误报，或"看不见却说没问题"

**依据与强度**从强到弱：母语者多人一致 > 有出处链接（写出处的读者是谁）> 脚本可复现 > 个人判断。
个人判断也可以交，维护者会先记着，攒到有更强依据再改规则。
